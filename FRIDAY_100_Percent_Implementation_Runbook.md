# 3. Immediate blockers before adding more autonomy

## 3.1 Remove false verification

The current `src/friday/computer/verification.py` still contains optimistic paths:

- `WindowVerifier` can return success even when no matching window was found.
- `ControlVerifier` returns success without checking the control state.
- `URLVerifier` returns success without checking actual browser state.

Fix these first.

The rule is absolute:

> A normal function return is not proof of success.

For every mutating action:

```text
observe before
    ↓
action
    ↓
observe after
    ↓
compare actual state with expected state
```

Only the final observation can establish `verified=True`.

---

## 3.2 Replace the fake streaming STT implementation

`src/friday/interaction/stt.py` contains a `StreamingTranscriber`, but `start_streaming()` currently initializes fields and returns without running a real microphone/partial-transcription loop.

The final implementation must be event-driven.

# 9. Docker security policy

FRIDAY's self-development containers should use:

```text
non-root user
no network by default
read-only source mount where possible
temporary writable workspace
CPU limit
memory limit
timeout
no Docker socket
no host secrets
no OAuth tokens
no SSH keys
no browser profiles
```

Never mount:

```text
\\.\pipe\docker_engine
```

or otherwise expose the host Docker daemon to candidate code.

Docker is one isolation layer, not an absolute security guarantee. Highly hostile code eventually deserves a VM/Hyper-V/WSL defense-in-depth boundary.

# 20. Turn detection

Turn detection is different from VAD.

VAD says:

```text
someone is speaking
```

Turn detection decides:

```text
the user has finished the request
```

Inputs:

```text
VAD state
partial transcript stability
pause duration
current conversation state
authorization state
wake state
```

Examples:

```text
"Open VS Code"
    -> END_TURN

"Open VS Code and then..."
    -> KEEP_LISTENING

FRIDAY speaking + "stop"
    -> INTERRUPT
```

# 24. Barge-in architecture

Interruption must cancel the whole active turn, not merely audio playback.

```text
speech detected while FRIDAY speaks
        ↓
InterruptionManager
        ├── stop playback
        ├── cancel TTS
        ├── cancel LLM stream
        ├── cancel interruptible tool planning
        ├── increment turn generation
        └── start new listening turn
```

Use a generation ID so stale results cannot overwrite the new turn.

This should apply to:

```text
STT
LLM
TTS
tool execution where safely cancelable
browser waits
computer waits
```
